RECOMMENDATION

原生窗格 + 预览器注册机制，先做随包插件。

建议把预览窗格作为工作区的第三种叶子，与终端、文件浏览器并列。宿主负责窗格、路径、端点、读取与生命周期，预览器负责内容呈现。第一阶段提供随包的 Markdown / HTML / 图片 / 文本预览器，网页使用独立的系统浏览视图。

插件化值得做，但“渲染器可替换”与“允许安装任意第三方代码”应分阶段。先统一协议和注册表，再验证受限的 HTML/JS 插件包；无需先造一个完整的 VS Code 扩展宿主。

跨平台共享的是数据契约、类型匹配、资源规则、测试夹具，以及可选的 Markdown 转换器或文档内容资产；窗格、工具栏、触摸操作仍用各端原生 UI。这里的 WebView 是内容渲染器，符合项目不使用跨端 UI 框架的方向。

把“点击路径”分成识别、解析、打开

桌面正式交互建议跟随 VS Code：⌘ + 点击，右键菜单提供“在旁边预览 / 外部打开 / 复制路径”。普通点击与拖选继续服务终端。Android 保留当前轻点唤起 IME / 鼠标操作，长按选中文字后提供“预览链接”动作，避免与已有输入规则冲突。另提供可键盘操作的“打开检测到的链接”列表。

  1. 识别：优先 OSC 8 明确链接，再识别 http(s)、file URI、绝对路径、带行列号路径。普通文本启发式只作为候选，不承诺所有单词可打开。
  2. 解析：生成 OpenTarget，携带端点 ID、会话 ID、原始 URI、规范路径、行列号、来源可信度、cwd 状态与请求代次。匹配后实际 stat / 读取，失败显示原因；扩展名不能覆盖真实内容检查。
  3. 相对路径：只有确定的行对应 cwd 才自动解析。新输出可跟踪 shell 集成目录锚点；旧回卷没有锚点时让用户选文件根目录。Android SAF 的 content URI 作为独立资源类型，不硬转成 POSIX 路径。
  4. 打开：第一次在来源窗格旁创建预览；后续替换同来源组的临时项。双击 / 固定保留标签；同一资源可聚焦既有项。目录进入文件窗格，未知格式显式“不支持”。
  5. 行列定位：app.json:12:3 打开只读源码并定位；Markdown 的源码行与渲染段落需要 source map，初版只在源码模式保证行列定位。

SSH 里的 localhost 是远端地址

来源是 SSH / tmux 时，http://localhost:5173 不直接交给本机 WebView。明确提示“连接 devbox 的 5173 端口”，用户操作后再建仅监听 loopback 的 SSH 转发。宿主持有转发 owner，关闭最后一个使用者时释放。现有公开核心头未发现可直接调用的转发服务；这一步须独立核实 / 实现，不能标成现成功能。

端口替换还要处理 absolute URL、WebSocket / HMR、Origin / Host、登录回调、Cookie 与 CSP。首片可以先支持普通网页导航，远端开发服务器另做端到端探针；不要承诺任意 Vite 项目无需配置。关闭自动跟随刷新，先由用户点刷新；本地文件监听可后续添加，远端不高频轮询。

WKURLSchemeHandler 的自定义 scheme 与 Android 的合成 HTTPS 并不具备完全相同的 Web 平台语义。统一的是 ResourceBroker 规则，不强求两端使用相同 URI；fetch、模块、Service Worker 等留给正常 http(s) 页面，不承诺文件预览可替代开发服务器。

Android 的 WebView 版本独立于系统 API，功能必须运行时探测；渲染进程退出时显示可重载错误页，不影响终端。网页与静态文档必须是独立配置的实例；WebView 默认可能共享数据状态，不能仅凭“新建一个 WebView”就宣称 Cookie / 存储已隔离。首片文档禁脚本、禁站点存储；真正的多 profile 隔离另做能力验证。

插件只扩展“怎么呈现”，宿主守住“能读什么”

可借鉴 VS Code 的只读 Custom Editor Provider：类型声明与文档模型在宿主侧，视图实例可以有多个。Ghosterm 无需兼容 VS Code 扩展 API，也无需 Node.js、扩展市场或通用命令执行能力。

两种 Provider，各自有合适的边界

随包原生 Provider：Swift / Kotlin 类在编译期注册，具备 open / refresh / suspend / dispose 生命周期，统一描述 MIME、扩展名、支持平台、优先级、限额与显示名称。图片和纯文本优先这一档；“插件”首先是一种模块结构，不意味着动态加载原生库。

受控 Web 内容插件：一个可校验的 manifest + HTML / CSS / JS / 静态资源包，适合 Mermaid、CSV 表格、日志可视化等后续需求。每个预览实例获得受限文档输入；不传宿主真实路径、密钥、SSH 句柄或任意文件读取函数。文档内脚本与插件自身脚本必须分开，插件脚本允许运行不等于用户 Markdown / HTML 可执行代码。

注册和权限

匹配顺序建议为用户显式“打开方式” → 已保存的类型关联 → 随包默认 Provider。用户文件名不能指定要执行的插件。多个匹配展示选择器；缺依赖、版本不兼容、平台不支持都显式报错。网页 BrowserProvider 是宿主内置能力，第三方 Provider 不能接管全部 http(s) 或自动建立隧道。

第三方阶段需新增宿主控制的授权界面、包来源 / hash / 签名策略、版本范围、升级和撤回、超时 / 内存预算、解压路径保护、许可证清单，以及禁用后恢复内置预览。CSP 和资源根目录是多层约束的一部分，不能称作完整恶意代码沙箱。先允许受审随包或明确受信的包；开放任意第三方安装前再完成隔离威胁模型与跨端攻击测试。

这项方案无需引入跨端 UI 框架。若第三方内容插件最终使用 HTML/JS，它也只绘制文档内容，窗格、按钮、文件权限与会话仍由原生宿主负责。

消息方向契约
open / update宿主 → Provider文档 ID、generation、MIME、displayName、有限字节内容或 scoped URI、主题、行列号
ready / errorProvider → 宿主requestId + generation；晚到和已销毁实例消息拒收；解析结果与读取成功分开
requestResourceProvider → 宿主只有 manifest 声明且用户授权后可用；相对路径、用途、限额；宿主校验后返回 opaque URI
requestOpenLinkProvider → 宿主用户手势关联，只发目标；宿主重走解析 / 权限，不允许插件执行终端命令
theme / visibility宿主 → Provider仅白名单主题 token；后台暂停动画 / 网络任务，不影响终端可见性管理
dispose宿主 → Provider撤销资源 token、取消读取、销毁视图；不依赖插件确认才回收宿主资源

桥接仅为受信插件文档启用：macOS 可用 WKScriptMessageHandler（校验 frame / 文档会话）；Android 优先探测 WebMessageListener，固定精确 origin 并检查 isMainFrame。API 不支持就明确拒绝该插件能力，不退回对任意网页开放 addJavascriptInterface。来源与主 frame 校验还不足以约束被攻陷的同源插件，所有能力调用仍必须独立核对范围、代次和额度。

远端资源、刷新和失败必须有明确语义

  • 独立 owner：预览不借用已失效终端或文件页的 native handle。远端经独立预览 / 文件服务 owner 重新验证来源，沿用主机密钥和认证流程，不绕过未知 / 拒绝状态。
  • 静态资源：HTML / Markdown 相对 CSS 与图片由 Broker 按需读取。规范化 percent encoding、路径分隔符和 dot segments，校验真实根 / 端点，拒绝越界和符号链接策略不满足的请求。SFTP v3 不能保证竞态下原子 no-follow，要沿用并公开现有保证边界。
  • 额度：首片 Markdown / 文本沿用 Android 的 256 KiB 产品上限；HTML 主文档、每个附件、合计字节、并发请求、像素和超时分别设置。图片可提案 16 MiB 压缩 / 32 MP 像素，但必须经两端内存探针决定，不是已验常量；不修改现有 Core 1 MiB preview 上限来凑功能。
  • 文档默认离线：自定义 scheme / PathHandler 仅供应授权资源；CSP、导航委托和请求拦截共同限制其它来源，远程图片展示“未加载”并由用户主动授权。不要只拦顶层跳转却遗漏 CSS、子帧、表单与重定向。
  • 脚本边界：静态 HTML 与转换后的 Markdown 禁脚本；cmark-gfm 不启用 UNSAFE，危险 URL、raw HTML、SVG、内嵌 frame 继续走白名单与夹具核验。网页 JS 不获得终端 / 文件桥。若后续允许交互 HTML，作为新模式重新设计授权。
  • 刷新：每次刷新是新 generation。文件变化、超额、编码错误、取消和权限丢失不折叠为成功。保留旧快照时明确“旧版本，刷新失败”，不能把部分下载结果渲染成完整文件。
  • 退出与缓存：关闭预览立即取消请求、撤销令牌，异步释放 owner；私有副本有配额、存活引用和显式清理策略。Android 进程重启恢复描述信息，不自动联网、重放授权或重建转发。
  • 网络策略：开发服务器的 loopback HTTP 要单独核验 macOS ATS 与 Android API 29 / 36 的明文策略，不能全局开放任意 HTTP 来解决 localhost。正常 HTTPS 校验证书，错误可见。
