# 原生会话凭据选择

`SessionCredentialSelector` 在主线程处理平台提示，独立串行线程读取身份文件和 Keychain。它复用共享认证流程提供的主机验证结果、认证方式表、请求标识和认证成功通知，不拥有 SSH 字节流。

只有发现服务器支持的认证方式后才读凭据。未加密私钥不读取口令缓存、不弹解锁框；未知格式明确提示后跳过。密码只在服务器允许时使用。没有可用身份文件属于认证失败；服务器只提供当前未实现的认证方式返回 unsupported。取消是独立结果，迟到的磁盘读取不得提交凭据。

用户新输入的密码或私钥口令只在服务器接受这一请求后保存，不能把提交材料当成认证成功。认证拒绝后先删除对应缓存，再读取下一候选。缓存账号区分私钥路径，或主机、端口及用户名；写入失败明确提示。新会话的默认身份候选由入口展开；恢复时仅使用记录中的身份引用，空列表表示使用密码。

身份文件必须是当前用户所有的私有常规文件，拒绝符号链接，读取限制 1 MiB；不会新增明文落盘。持久化会话元数据只保存身份路径。认证过程中解锁材料只在内存中移交 C 核心。

证据：5 项原生测试覆盖方式表先于取密、未加密钥匙、成功后保存、拒绝后清缓存、迟到结果与未知格式。`python3 scripts/mutation-check-session-credentials.py` 包含 6 项隔离变异，每项要求普通 XCTest 断言失败和同变异对照通过，并检查标记预扫、信号回滚与 SHA256。Keychain 测试注入存储，不访问开发者真实凭据；真实 SSH 接受/拒绝及请求范围另由共享认证和 Linux 安装探针验证。

此切片提供应用平台凭据适配器。默认应用入口切换和恢复列表由后续会话协调器接入，不应据此宣称默认流程已经交付。
