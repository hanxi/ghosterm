# macOS 终端设置存储

设置文件仍是 Ghostty 语法，由引擎解析；UserDefaults 应用偏好不进入该文件。`SettingsStore` 复用原生 `ConfigStore` 的字节/设备/inode/权限/纳秒时间快照、稳定非阻塞锁、强制备份、同目录完整暂存与原子替换。Settings 的备份保持原有 `ghostty.conf.bak` 命名；SSH 存储保持原先去扩展名的 `.bak` 规则，不为复用更改用户备份位置。

只有 ENOENT 是空文件；目录、链接、读取失败、非法 UTF-8 与 NUL 均保留错误。`rawConfig()` 现在抛错，展示缓存与读取错误分开；加载失败的缓冲区不得保存。外部新建、等长/同 mtime 替换、删除及变化都会导致保存冲突。读取与提交使用同一份捕获快照，不在写盘前偷偷读入外部文本并冒充用户已审阅。

第一次保存可建立缺失的应用配置父目录与 0600 文件。已有文件保持权限/所有者，备份为独占私有文件；备份拒绝不删旧备份或目标。rename 后错误明确返回已提交，Settings 缓存也失效，不能再次保存或把旧内容当当前磁盘成功状态。必须显式重新读取核对；不承诺对不合作写入者提供原子 CAS 或 ACL/xattr/断电持久性。

设置页配置区在读取错误时显示错误并禁止保存，提供“重新读取”。此动作只更新文件快照与编辑缓冲区，不宣称引擎已经应用；标题改为“已加载的配置文件”。保存才调用原有应用流程。读取失败后即使文件随后恢复，也须通过该动作采纳新内容，不能将空编辑器写回。

稀疏合并更新标量的最后一条本地声明，与标量回显一致；删除清除该键的全部本地声明，避免旧值重新露出。CRLF 以字节换行分隔，其他行/顺序/注释和尾换行保留，目标行保持原来的 CRLF。空值声明可识别。`value` 仅是单键原文查询，不是累计项的引擎求值；字体选择仍由 `TerminalFontSelection` 显式清除本地 fallback 声明再选择单一字体，其他重复项保留原文，不把它们描述为标量。

## 第十批：候选校验、提交与实际回显

普通设置、字体选择和全文编辑共用一条路径：确认加载快照/编辑窗口未过期，使用最终绝对路径在内存中准备 Ghostty 配置，提交主文件，最后应用保留的解析对象。无效候选不会写主文件或备份，也不会先修改已有 surface；提交失败不得应用准备态。不再先覆盖磁盘后用一次不检查结果的写入去恢复旧文本。

`0004-config-candidate.patch` 为锁定 full libghostty 增加两个入口：checked 内存配置加载与 checked App 更新。原生 LineIterator、路径展开、递归 config-file、条件重放及 finalize 都由上游实现；不使用临时文件名替代逻辑根路径，不另写一份语法解析器。输入限 16 MiB、UTF-8/无 NUL，同时校验深浅色分支；必需文件缺失失败，上游显式 `?` 可选缺失才允许。指向当前根的直接引用或链接别名明确拒绝，避免用旧根内容为未保存的候选背书。硬链接别名按保守限制处理，不假定提交后的链接拓扑。

准备态拥有本次解析结果，应用不再重读主文件或附加文件。附加文件之后的变化不会混入本次应用，但这不是多文件磁盘原子快照；下一次启动/加载会重新验证。全文编辑窗口捕获原快照，不能覆盖另一个设置操作后来保存的内容。存在附加配置时快捷字体/字号/主题控件明确只读，要求通过配置文件编辑，避免改了主文件却被附加声明覆盖。

应用错误分开记账：校验或提交前失败保留旧目标和引擎；rename 后同步/回读失败报告主文件已提交，缓存失效且不应用候选。文件已成功提交、引擎运行期更新失败时，C 层检查旧配置恢复请求是否被接受；恢复失败明确返回状态未确认，宿主报告“已保存但终端应用未确认”，不盲目覆盖磁盘或自动重试。它不是磁盘与所有 surface 的原子事务，也不是完整 OOM/renderer 释放验收。

数值/布尔回显来自当前应用后的条件配置克隆，保留源配置用于后续主题重放；深浅色切换后不能继续读取另一分支的字号。文件“重新读取”只更新编辑缓冲区，不能把还没应用的值呈现为已生效。外观页初始化字号时不保存；真实控件与文件/备份/修订号共同验证这一点。复杂主题/字体的来源展示与标量实际读取分开，不把单键文本查询当完整引擎求值。
