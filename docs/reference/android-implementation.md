### 返回、会话与连接状态

**返回优先级**：先交给正在编辑的系统 IME 收起键盘；有模态面板时关闭面板；文件选择模式退出选择；目录内返回上级；分类设置回总览；其他页面回其来源，终端回主机。首页交还系统返回行为。返回不等同断开；页面销毁不直接释放连接。预测性返回与顶栏返回应获得相同目标，取消手势不修改状态。

**会话身份**：`SessionId` 使用独立 UUID，不使用主机名充当 ID。首页点击已连接主机时回到该主机最近活动的会话；若同主机有多个连接，进入会话面板选择。“新建会话”允许同主机再开连接。主机改名不改变活动连接身份；编辑地址只影响下一次连接。HTML 以 host ID 简化会话数量，原生实现不得照搬该限制。

**连接状态**：未连接、解析地址、连接中、待主机验证、待凭据、已连接、失败、已断开分开显示。查不到状态不显示“已连接”；文件连接成功不等于终端已连接。连接中允许取消；晚到的 DNS/认证结果必须携带请求 ID 与 generation，不能落到已关闭页面或另一条会话。

**原型与当前实现的差异**：上表是最终交付要求。本地与普通远端会话已接入（§9.27）；底栏暂为主机/会话/键盘；文件入口随 A4 接入。已提交设置只有配置与关于，工作区另有 SSH 身份入口但验收未完成（§9.32）；五类偏好及默认 12sp 尚未实现，终端当前使用 14sp。已提交终端文本操作见 §9.14，后续选区/Ctrl 与 Gboard 进度见 §9.15–§9.16；它不实现文件页的勾选、复制清单或跨端点粘贴，也不改变 macOS 原生文件列表的单击选择/双击打开习惯。

## 3. 模块与线程设计

模块目录（app/bridge/terminal/domain/data 已建；下列 owner、事件泵、会话/文件模型与 TerminalView 为目标职责，尚未全部实现）：

```text
android/
  settings.gradle.kts / build.gradle.kts / gradle/libs.versions.toml
  app/src/main/                       Activity、导航、Compose 页面、资源
  domain/                             会话/主机/文件/任务状态与用例
  data/                               配置事务、设置、身份、SAF、文件后端
  bridge/src/main/cpp/                C ABI 绑定、owner 注册表、事件泵
  bridge/src/main/java/               类型化句柄包装与低频结果转换
terminal/android/
  src/main/                           TerminalView、InputConnection、surface 接缝
  native/                             VT 桥、渲染状态与原生数据通路
```

Gradle 模块引用 `terminal/android` 的 source/project，不把实现再复制进宿主。终端数据链为
`UI → TerminalSurface → Transport → Core`；配置、认证、文件控制面经对应 controller/repository 与类型化 bridge 进入 Core，不能为满足图示而让文件操作经过终端。Composable 不接触 JNI、C 句柄或 libssh2。

- **主线程**：Compose 状态、输入事件、系统授权、IME、View 挂载；不执行 DNS、磁盘、大目录扫描或阻塞 JNI。
- **终端 owner**：每条连接一个串行所有者，唯一调用 `gt_transport_read/write/resize/close`。输出直接送 VT，禁止转为 Kotlin `String`、Flow、UI 消息或逐字节 JNI 回调。
- **渲染**：读取受控的 VT 渲染状态/快照，主线程最多收到合帧的“需刷新”信号。首片选 Canvas 验证正确性，生产自绘方案在 A2 的持续输出、滚动、内存验证后固定；不足时换 GLES，但保持同一 surface 接缝。
- **文件 owner**：SFTP 使用独立 SSH 连接；目录调用不与其他线程同时使用同一会话，每个核心 SSH 会话的单 I/O worker 推进其传输。传输任务持有后端租约，不依附文件页面；目录/冲突查询、入队、控制与释放均不能让主线程同步等待 owner。串行队列本身不提供 UI 响应性保证。
- **全局事件泵**：只允许一个消费者调用 `gt_core_poll_events`，按 job ID 扇出；当前进度在 `message` 中编码为 `sftp done/total`，桥层集中解析与校验，页面不解析字符串。无法解析时显示进度未知，不能猜百分比。
- **事件终态可靠性**：当前 Core 事件队列容量 256，满时覆盖最旧事件，没有 job 终态查询 ABI。A6 必须验证事件消费能力，并补足终态保留/查询等共享保障；不得通过百分比或超时猜测成功。
- **关闭**：发取消、停止提交输入、owner 有界退出后释放 transport，再释放借用的 SSH，最后安全释放 surface。UI 不同步 join；JNI close 幂等，禁止裸指针反复使用。

JNI 只经 `core/include/ghosterm.h` 引入共享核心；VT C API 只在 terminal 模块内使用，这是引擎边界，不是第二套 Core ABI。句柄采用带代次的注册表，拒绝已释放 ID。字符串显式 UTF-8 编解码，拒绝内嵌 NUL；不要用 JNI modified UTF-8 直接代替文件名与终端 UTF-8。日志只记录错误码、阶段和匿名请求 ID，不写凭据或终端原文。

## 4. 主机、配置与认证

### 4.1 主机列表与编辑

`ssh_config` 是唯一主机配置真相，放在 App 私有配置目录；列表为派生视图，不另存一份 host JSON。首次没有配置显示空态；读取/解析失败显示错误与重试，不能变成空列表。`Host *` 等规则块不是可连接主机，在配置入口显示和编辑，不当作工作/个人分组。

编辑页至少包含别名、HostName、User、Port、身份选择及高级指令查看。别名不能为空；显式地址/用户名不能为空，显式端口为 1–65535；Android 不把进程 UID 用户名作为远端登录名默认值。显示继承值与当前块显式值，未触碰的字段不能回填覆盖全局规则。

**当前表单边界**：别名只允许 1–128 位 ASCII 字母/数字及点、短横线、下划线，首位必须为字母或数字；归属明确的主文件主机可直接改名，保持同块其他别名与非目标配置字节；包含文件/重名块只读，目标冲突明确报错，见 §9.9。HostName/User/Port 均可单独切换“使用继承值”，继承 User 缺省允许为空；这不表示连接时会自动选择远端用户名。连接参数目前只有这三个字段，身份选择尚未接入。`169cc60` 曾要求所有保存的 User 非空，§9.7 已按字段模式修正。

A1 收尾须明确编辑对象，不能仅以最终生效值反推原配置：

| 情形 | 实现契约 | 验收结果 |
|---|---|---|
| 显式值与继承值 | Core 提供字段来源/目标块元数据，桥层转换；UI 显示“此主机设置”或继承来源，脏字段单独跟踪 | 未编辑的继承字段不生成新指令；设置为与继承值相同的显式覆盖也能准确表达 |
| 多别名 `Host a b` | 编辑前列出同块别名，说明修改影响整块；不得在不提示时只展示 `a` 却修改 `b` | 保存后两者求值与确认范围一致，其他块逐字不变 |
| 重名块与 Include | 来源必须能区分主文件/包含文件及块；首版只允许归属明确的主文件块表单编辑，包含文件显示来源和限制 | 不向错误块追加相同别名，不改 Include 外部源；无法安全定位时明确拒绝 |
| 别名重命名 | 仅改目标 Host 行，检查大小写无关冲突，保留其他别名/行；主机引用与活动会话身份分别处理 | 只改名时保留地址/User/Port 指令原文与未知行；重新求值可能因默认 HostName 或通配匹配改变而得到不同结果。活动连接保持原快照和身份（A3 验）；不能用 reset 整块重建替代改名 |
| 复杂重复指令 | 已修共享编辑器按实际匹配行修改；Android 原文检查继续防止无关行变化，见 §9.4 | 重复字段之间的注释、未知指令和其他字段原字节保留；同时回归 Apple 调用方 |

`gt_config_inspect_host` 已提供 HostName/User/Port 来源与块归属，Swift/JNI 已同步；Android 表单已展示来源、多别名影响和只读原因，详见 §9.5。它只查询三个连接字段，不能代替完整块视图或改名操作；改名使用单独的 `gt_config_rename_host`，见 §9.9。未改字段继续不写回；§9.7 已交付“显式设置为与继承值相同”和“恢复继承”的独立编辑状态；不得在 Kotlin 写第二份 SSH 配置求值器；A1 完成状态以 §9.11 的退出验收为准，不由单一字段切片决定。

只给真正接入的连接选项提供可用控件。C 的配置求值能返回 ProxyJump、转发、ServerAlive 等字段，不代表 SSH 执行层支持它们；检测到影响连接且未支持的显式配置时，列出指令并报不支持，不悄悄绕过。未知指令仍需无损保留。

共享连接前检查已按 §9.24 接入两端：macOS `HostListModel` 保留检查结果与来源，连接目标携带快照，认证流程在 DNS 前拒绝未支持配置；Android 主机按钮显示同一规则产生的问题。高级选项执行仍未实现，42 键求值对拍不能视为全部选项可连接；允许范围、保守拒绝边界及 SSH/SFTP/tmux 产品证据见该节。Android SSH JNI/后端已在 §9.25 接入；产品 DNS/认证 UI 首片与剩余验收见 §9.27。

#### A1 字段编辑契约（已按 §9.7 实现）

每个字段分别保存“继承/显式”模式和输入草稿，不能只比较输入与最终生效值。下表行为在 §9.7 补齐并通过设备/变异验证；§9.5 的来源展示本身不包含这些编辑能力。

| 场景 | 表单与保存行为 | 必须验证 |
|---|---|---|
| 原块没有指令 | “使用继承值”开启，展示只读生效值与来源；关闭后允许输入显式值 | 不修改时不生成指令；显式设为相同文本也能写入 |
| 原块已有指令 | 输入框显示本块显式值；若被更早规则遮蔽，另列当前生效值和来源 | 编辑其他字段不能覆盖未触碰的被遮蔽值 |
| 从显式恢复继承 | 记录删除该字段的意图；尚未保存时说明“保存后重新求值”，不把旧值冒充新的继承结果 | JNI 将删除转换为 Core 的空 values，而非空字符串；只移除目标指令 |
| 切回原模式 | 保留输入草稿，但脏状态只比较最终写入意图 | 切换后还原不弹误报的放弃确认；真正修改时退出须确认 |
| 新主机全部继承 | 允许创建只有 Host 行的配置；地址/User/Port 由 Core 重新求值 | 不因修改映射为空而把新建误判为无操作；缺省 User 可为空，连接时再校验 |
| 显式值被更早规则覆盖 | 保存前以候选配置查询显式值与获胜来源；拒绝无法兑现的新增覆盖并保留草稿 | 不改原文、不写假成功；引导到配置页调整规则 |

验证只约束显式输入：非空合法地址/用户名、端口 1–65535；继承模式允许缺省用户名为空。只读块禁用输入与模式切换，但配置来源入口仍可用。仓库保存前再次检查归属，不能仅依赖页面禁用。

实现链为领域编辑状态 → 可空删除值的 JNI → 候选配置校验 → 表单开关/来源/返回确认。设备测试操作真实开关、保存和返回按钮，覆盖同值显式覆盖、三个字段全部恢复默认、全部继承的新建、验证失败保留草稿与模式还原；配置测试另验删除最后一条 User、被遮蔽值保留和候选编辑保护。身份选择、重命名与 SAF 全流程不在本片验收内。

### 4.2 配置写入事务

Android 新实现必须按以下顺序完成，不能照搬现有 Apple `ConfigStore` 的失败处理：

1. 读取原始字节、文件身份和内容摘要；UI 编辑生成稀疏修改。
2. 保存前重新检查摘要/身份；发生外部变化则提示重载，不覆盖。
3. 强制备份原字节；备份失败就停止。首次创建没有原文件时不伪造备份。
4. 同目录独占临时文件写入、flush/fsync；用平台支持的原子替换提交，不能先删目标再移动；同步目录并清理失败临时文件。
5. 提交前失败保留旧文件；提交成功后重新读取、解析并更新摘要。若替换已成功但目录同步或回读失败，必须说明“已提交但验证/持久化失败”，不能谎称原文件没变，也不能盲目回滚覆盖后来变化。

当前锁保护同进程仓库及遵守 `.config.lock` 的协作写入者，摘要复核覆盖加载后和暂存期间的变化；它不是针对任意不遵守锁的写入者的文件系统 compare-and-swap。最后一次复核与 rename 之间仍有竞态窗口，不能把 API 36 模拟器故障注入结果扩大成任意并发写入都不会丢失。私有目录/单一写入入口是当前约束；将来开放其他写入入口须共享同一锁与事务协议。

导入通过系统文件选择器读取授权文档，在私有目录保存被用户确认的副本；不承诺持续修改外部 provider 文档。`Include` 与 `~` 在 core 中有桌面路径语义，Android 需先验证私有 HOME 与 Include 基准；首片遇到不可访问的 Include 明确报错，不静默漏掉规则，也不重写用户配置为自造语义。

**现有 macOS 缺口**：`ConfigStore.save` 的备份使用 `try?`，写回先 remove 再 move；它不满足强制备份和完整原子替换。此为待修复实现缺口，见[路线图](roadmap.md)，不是降低规则的理由。

### 4.3 身份与主机验证

**共享前置、Android 后端与产品页面首片已接**：known_hosts 读侧保留标记，匹配的 `@revoked` 优先于普通信任记录；CA-only、当前主机的未知标记和已解析的 hashed 条目显式报不支持，读取错误明确失败。同步/公开异步 API 与 macOS SFTP 产品认证已验证，详见 §9.22。Android JNI/类型化状态已按 §9.25 保留 `GT_SSH_AUTH_HOST_REVOKED`；后续页面不得提供接受入口。连接前配置检查见 §9.24；DNS/认证 UI 与 Keystore 容器首片见 §9.27，整个 A3 仍未完成。

使用 `gt_ssh_authenticator_open/step/info/decide/supply/take/close`。DNS 在后台完成，原始 hostname 保留给 hostkey 身份；总 deadline 跨越用户提示，切换页面/取消不重置计时。未知主机显示地址、端口、算法、SHA256 指纹，用户明确选择信任或拒绝；密钥变化或已撤销直接阻止并提示核对，禁止自动覆盖 known_hosts。能力不支持和读取失败分别显示原因，不转成未知主机确认。用户接受后若保存失败，显示 IO 原因并停止，不继续索取凭据；共享及 macOS 接线见 §9.23，Android native 失败路径验证见 §9.25，产品页面首片验收见 §9.27。

先发现服务器认证方式，再索取受支持的凭据。无口令钥匙不弹口令框；格式未知不伪装成“口令错误”。当前公有入口支持密码和 PEM 私钥，不能因为方法掩码存在就声称已支持任意 keyboard-interactive、agent、硬件签名或 hostbased。

Android Keystore 的不可导出私钥不能直接转成 `gt_ssh_auth_private_key` 所需 PEM。当前首片采用每身份一个 Keystore AES-GCM 密钥，SSH 导入材料只进入其保护的加密容器；授权后短暂解密至内存供 core 使用，凭据页面/配置只保存引用，不保留明文文件。不能声称这种方案是 SSH 私钥永不离开硬件的签名代理；后者需要新的共享签名契约。[Keystore 官方说明](https://developer.android.com/privacy-and-security/keystore)

凭据使用可清理缓冲，失败/取消后擦除；禁用凭据备份和调试日志。Keystore 失效或设备凭据变化应要求重新导入/解锁，不回落明文。导入权限属于临时授权，不自动删除用户原文件。身份页面提供名称、类型、指纹、引用主机与移除确认；主机验证页面只展示真实记录，移除信任后下次重新核对。

## 5. 终端与移动端输入

`TerminalSurface` 只接收字节、尺寸、外观、焦点和输入，不知道 SSH、本地或 tmux。VT 构建只使用锁定 pin 的头与库；不得把 Apple full libghostty 的配置/Metal shim 搬来假装 Android 有渲染后端。

| 项目 | 实现要求 |
|---|---|
| 渲染 | 真 VT 网格；ANSI 颜色、宽字符、组合字符、emoji、反色/下划线、光标、选区、滚动与备用屏幕；不以日志 TextView 代替 |
| 字体 | 首版系统等宽字体；测量真实字形，宽字符占格一致；字号变化更新像素与 cols/rows |
| 尺寸 | 内容区扣除状态栏、底部控制、辅助键及 IME insets；同一尺寸下发 VT 与 transport；合帧且拒绝零尺寸 |
| 输入 | `TerminalView` 实现 InputConnection；组合串只本地显示，commit 才编码发送；中文提交不套 bracketed paste |
| 辅助键 | Esc/Ctrl/Tab/四方向，加 `/`、`-`；扩展增加 Home/End/PgUp/PgDn；根据 VT 模式编码，不硬编码所有方向键字节 |
| Ctrl | 单次发送后释放；锁定再点解除；会话切换/断开清修饰状态，防串到另一会话 |
| 系统键盘 | 一个开关；状态来自实际 IME 可见性；外接键盘仍可输入；自动弹出只作用于新连接 |
| 文本粘贴 | 与文件剪贴板分离；走 VT paste 编码，尊重 bracketed paste；不能把文件卡片贴入 shell |
| 清屏 | 只清本地终端显示/滚动历史，明确作用范围；不向 shell 注入 `clear`、Ctrl+C 或回车，不中断命令 |
| 后台 | 不可见 surface 停止绘制但保持 owner 读流；断线显示实际状态；进程被杀不伪装会话仍连接 |

InputConnection 应覆盖 composing/commit/deleteSurroundingText/sendKeyEvent、组合取消与焦点切换，不能只支持示意键盘的点击。[BaseInputConnection](https://developer.android.com/reference/android/view/inputmethod/BaseInputConnection)

首版本地终端显式尝试 `/system/bin/sh`，设置私有 HOME/cwd 与 TERM，不把 `/bin/sh` 桌面默认值带进 Android；只获得 App UID 的权限。若设备不支持 PTY 或 shell，显示不支持与原因；不偷偷换成无 PTY 命令执行。Termux/proot 另列 A9，不阻塞 SSH 交付。

### 5.1 终端文本动作与状态

下列链路已在 `12c88ba` 接入，设备与变异结果见 §9.14；`294dda6` 补齐边缘滚动、锚点跨越及 Ctrl 生命周期，证据见 §9.15。§9.16 已补真实 Gboard 拼音候选、删除及提交的基本路径证据；完整软硬键盘矩阵与性能仍属于 A2 退出条件。

| 动作 | 页面及引擎行为 | 生命周期与错误 |
|---|---|---|
| 长按选择 | 坐标转为 VT 当前 viewport 的格子引用，按词选择；浮动工具条提供复制/粘贴/全选，选区与手柄跟随真实 VT 状态 | 长按空白清除旧选区；点按或退出工具条清选择；持有边缘手柄每 80ms 滚动并原子更新端点，松手/取消停止；跨锚点与重新抓取已验 |
| 调整与复制 | 手柄修改选区端点，VT formatter 处理软换行、宽字符、组合字符与尾部空白；用户确认复制后才写系统剪贴板 | 空选区报“没有选中的文本”，保留已有系统剪贴板；结果最多 1 MiB，不截断后冒充完整复制 |
| 粘贴 | 仅用户触发时读取单项文本；交 VT paste 按当前 bracketed-paste 等模式编码 | 不接受文件 URI 强制转换；拒绝时零输入并保持连接，显示确认；确认重试原文本快照，取消不发送 |
| 清除本地显示 | 顶栏菜单先确认，清当前屏幕及其历史、选区和图像；保留 cursor、mode、parser、另一屏幕及正在运行的命令 | 不发送 `clear`、FF、Ctrl+C 或回车；引擎错误显示到页面，不虚报清除成功 |
| 正常 EOF 后浏览 | Transport 关闭，VT 与 owner 保留到用户显式关闭，仍可滚动、选择、复制和清本地显示 | 不再允许粘贴输入；错误退出后的内容保留尚不在保证范围；会话不能显示为已连接 |

`LocalSession` 用互斥锁串行提交文本请求；JNI 的 begin/read/end 使用 request ID，结果槽由 native owner 写入。协程取消也须归还槽，晚到结果不能占据下一请求；页面移除时关闭工具条/确认框，不将 UI 旧请求转到新 surface。普通终端输出仍直接从 Transport 进入 VT，复制只按用户请求返回所选文本。

系统上下文菜单、Ctrl+Shift+C/V、Shift+Insert 与无障碍入口复用上述动作；存在入口不等于完整 TalkBack 或物理键盘验收。文本剪贴板与 §6 的应用文件清单是不同模型，文件任务完成不能清系统文本剪贴板。

macOS 对照时须注意：`beffb49` 已接 `TerminalHostView.copy:` / `paste:`，真实选区写入系统剪贴板，系统字符串经 `sendText` 进行模式感知粘贴。专用测试显式指定 firstResponder，尚不证明全局主菜单自动路由；引擎读写/确认回调、选中自动复制与粘贴确认仍未接通，见[路线图 P1](roadmap.md#macos-下一步与共享缺口)。Android 文本操作与文件路径复制不能替代这些 macOS 余项的验收。

## 6. 文件浏览与复制粘贴

### 6.1 位置与浏览模型

`FileLocation = endpoint + directory`，端点分为应用私有目录、本机 SAF 授权树、远端主机。远端身份含配置引用与解析后的 host/user/port，不用显示名称、当前终端或文件名推断来源。使用独立 `FileEntryId`，文件原始标识与展示名分开；不把 `content://` 转换为猜测的 Linux 路径。

本机默认显示应用文件，并提供“选择设备文件夹”；原型中的 Download/Documents 只是模拟条目，不能据此申请全盘权限。SAF 返回 URI 授权，重启后使用持久授权前需核验；撤销、移动和 provider 失效都显示错误与重新选择入口。[Android 文件访问说明](https://developer.android.com/training/data-storage/shared/documents-files)

远端首次进入查询真实 home/realpath；不把原型 `/home/deploy/ghosterm` 当默认路径，也不声称跟随 shell cwd。每个端点保存本次进程内最后目录，切换位置清选择、保留复制清单。请求携带位置 generation，旧目录晚到结果不覆盖新目录。加载中、合法空目录、权限拒绝、断线分别呈现。

默认点击目录进入、点击文件只读预览/打开；远端预览按需下载受控临时副本，大文件限额并明确提示。长按通过系统手势进入选择并选中当前项，滚动取消长按；TalkBack 和外接键盘可用“选择”入口。选择模式中点按只切换勾选，“全选”只作用于当前可见过滤结果，不递归选择目录内容；复制按钮在零项时禁用。

### 6.2 应用内待粘贴清单

```text
ClipboardSnapshot
  id: UUID
  sourceEndpoint / sourceDirectory
  items: [entryId, rawName, kind, size?, mtime?]
  createdAt
PasteRequest
  id: UUID
  clipboardId + 独立的源条目快照
  destinationEndpoint / destinationDirectory
  conflictPolicy + perItemDecisions
```

复制只创建清单，不传输；完成后退出选择模式。卡片显示来源主机/本机、源路径、名称摘要、数量和“查看清单”；底部“粘贴到当前目录”。切到设置、终端、另一主机仍保留；新复制明确替换旧清单。它不是 Android 系统文本剪贴板，不向其他 App 泄露远端路径。

粘贴前固定源和目标快照，确认页列出两端路径、条目数、冲突及本次策略。确认后导航不能更改目的地。来源失效、目标只读、同一目录无意义复制、目录复制到自身/后代、权限丢失、已有任务占用等均给出明确原因；不能只把按钮灰掉。

### 6.3 四种方向与 ABI 缺口

| 源 → 目标 | 首版路径 | 限制与补齐 |
|---|---|---|
| 本机 → 本机 | 私有文件或 SAF 的流式复制 | provider 不支持创建/写入时明确失败；不依赖真实路径 |
| 本机 → 远端 | 私有文件可走上传；SAF 先流式写入 App 私有暂存，再上传 | 现有 upload 只有路径参数；空间不足在写远端前报错 |
| 远端 → 本机 | 下载到任务私有暂存，再提交至私有文件/SAF 文档 | 两阶段都成功才标完成；下载完成不代表 SAF 写入成功 |
| 远端 → 远端 | 同主机和跨主机均先下载暂存，再上传目标专用连接 | 明示“经本机中转”；不执行拼接的 `cp/scp`；首版不声称服务器端复制 |

暂存按任务 UUID 管理、单文件逐项推进、有容量预算，退出/失败清理；数据敏感性与原文件相同，不进共享缓存或日志。应用自身设备目录与仓库开发 `tmp/` 是不同边界。关闭文件页面不取消任务；清空/更换清单也不取消已确认任务。

**阻塞完整交付的 Core 缺口**：`gt_sftp_upload/download` 没有 exclusive-create、fd/URI 或非覆盖提交参数。上传当前以 WRITE|CREAT 打开，下载以 `fopen(...,"wb")` 打开；不能把“先 stat 再写入”当成防覆盖，也不能把现有 upload 当作可靠覆盖（没有 TRUNC 契约）。A5 必须先补非覆盖创建/提交能力或等价可证明的契约，再启用正式复制。新增 C ABI 经聚合头、各端绑定及 ABI 对拍同步，不通过 Android JNI 直接调用 libssh2 绕过去。

还须核验**关闭与提交**：当前 `job_download` 先打开并截断本地目标，再尝试远端打开；上传/下载都没有检查远端 close 和本地 `fclose` 的结果。因此不能把现有 `GT_JOB_OK` 等同于目标已完整提交，也不能直接把用户现有文件作为下载中间产物。A5 使用任务独占暂存，分别验证写入、关闭、最终提交，失败保留原目标；A6 仅在全部必需步骤成功后发布终态。注入远端打开失败、缓冲关闭失败及远端关闭失败，并保留正常内容哈希对照；磁盘断电持久性是另一个契约，不由关闭成功推断。

### 6.4 冲突、递归与任务状态

- 默认“逐项确认”，仅提供“保留两者”“跳过”；首版不提供覆盖/移动/删除源。目录同名同样询问，不隐式合并。重名自动编号要独占创建并处理重试，不仅检查字符串列表。
- 建任务时扫描目录并保留相对路径、空目录；拒绝 `..`、绝对子路径和越过授权根的路径。首版不跟随符号链接递归；当前缺少创建链接 ABI，遇到链接明确报告不支持并让用户跳过，不能默默复制目标文件。
- 源在扫描后变化：执行前校验已知 size/mtime/type；不能证明一致时提示变化，不能声称是原始快照。大目录扫描可取消，数量未知时用不定进度。
- 状态包含 queued/scanning/awaitingDecision/running/paused/succeeded/partial/failed/cancelled/interrupted；UI 展示已复制、跳过、失败数量。核心 `OK/FAILED/CANCELLED` 只决定单 job 结果，父任务由全部子项汇总。
- 两阶段中转的传输字节与逻辑完成量分开，不能下载一半就显示整项完成；总量未知不伪造 ETA。暂停为分块协作式，不承诺瞬停；取消后列明已完成项与待清理临时项。
- 暂停/继续/取消分别记录请求中、已确认、明确拒绝或无法确认；仅发出请求不能更新为已暂停/已取消。后端抛错必须显示原因；取消完成前保留任务 owner，迟到事件按任务 ID/代次处理。未知 job 结果显示“结果未知”，不能直接当失败或成功；待状态可靠后才允许重试。
- 断线不自动恢复/重传；重试由用户发起，复核来源、目标与冲突。进程死亡后普通任务不恢复执行，清理清单与残留；必要的清理日志只含任务自有路径，不存凭据。
- “完成后清空”只在实际复制全部成功且至少复制一项时生效；全部跳过、部分成功、取消、失败保留清单。比较 clipboard UUID，旧任务结束绝不清掉后来新复制的内容。

macOS `TransferManager` 可作为正常路由对照，但目前仍忽略控制异常并把未知终态折为失败；Android 不照搬这两处行为。共享终态保障与 Apple 异常路径修复独立列在[路线图](roadmap.md#macos-下一步与共享缺口)。

**扫描与调度边界**：共享 `gt_sftp_walk(..., -1, ...)` 当前没有硬深度限制；只有正深度超过 64 时会被限制为 64。Android 需明确深度/条目/暂存预算，超预算显示扫描不完整，不把受限扫描当整目录成功。Core 的 FIFO worker 属于每个 `gt_sftp_t`；全局事件泵和全局任务列表都不限制跨连接并发。A6 首版可采用单个全局活动文件任务的调度策略，在 App 层持有调度权；中转任务串行完成下载与上传，不新增原型中不存在的并发设置。用两台远端的任务验证上限、取消后释放名额与后续任务继续，不能只测单连接队列。

**目标查询和取消契约**：存在性查询必须保留“存在 / 明确不存在 / 无法查询”三种结果；权限错误或断线不能折为不存在，只有明确不存在才可尝试独占创建。macOS `SFTPFileBackend.exists` 当前使用 `try? lstat` 转 Bool，不能直接用作 Android 的接口模板。目录扫描或搜索取消必须传入 owner；页面 generation 只解决旧结果覆盖，不能代替取消正在执行的 I/O。若后续用 exec 搜索，须检查退出状态、保留错误与部分结果，只在明确不支持时显示可选的 walk 路径；macOS 这些行为仍有缺口，见 [Apple 说明](../../apple/README.md#文件查询与线程边界)。

目录树与批量操作也必须保持错误可见：列目录失败不缓存成合法空节点，重新展开可重试；搜索遍历失败保留已发现结果并标明不完整。若后续提供递归权限操作，扫描失败与子项修改失败都要汇总，不能只捕获 chmod 错误。macOS 当前这三条路径仍吞掉部分错误，见 [Apple 文件查询说明](../../apple/README.md#文件查询与线程边界)，不能将其直接作为移动端实现模板。

## 7. 设置数据与作用域

使用版本化、类型化持久偏好（拟采用 DataStore），不把 Activity 内存或 HTML 全局变量当存储。页面行显示当前值；读写失败可见且不虚报保存成功。首次值按下表；非法值回默认并记录不含隐私的诊断。更改立即更新预览；写入失败回滚或明确显示未保存状态。

## 8. 生命周期、后台与系统适配

首版保证前台及页面/Activity 重建内连接所有权稳定，SessionRegistry 不绑定 Composable 销毁。旋转、主题切换、IME 出入只改变 View 与尺寸，不重连、不丢输出、不重复认证。内存压力与 App 进程死亡后重新启动回主机页，旧会话显示不得恢复为已连接。

普通 SSH 不承诺 App 后台常驻。若提供离开前台后的可见传输服务，应单独验证服务类型、通知、用户停止、超时和取消；不能借 `dataSync` 宣称无限 SSH 保活，Android 对该类前台服务有时限。[前台服务时限](https://developer.android.com/develop/background-work/services/fgs/timeout)

tmux 在 A8 接入，共享 `gt_tmux_*` 管理与普通 transport attach；用户显式打开列表才探测，缺失、版本不支持、拒绝与未知分开。HTML 的固定“未安装”只是演示分支，原生必须展示真实结果。关闭只断客户端，不结束后台 session；结束是单独确认动作。重新连接必须取新列表，禁止按旧 ID/名称恢复。手机本地 tmux 不因远端支持而自动成为可用能力。

A0 已锁定 minSdk 29、compile/target 36、arm64-v8a 及工具链版本（§9.1）；现有运行证据仅为 API 36 arm64、4 KB 页模拟器。API 29 声明下限、真机与 16 KB page size 装载均须在 A10 验证；x86_64 须先提供对应 native 库。不能只调整 APK zip 对齐就声明全 native 依赖可运行。[16 KB 页面支持](https://developer.android.com/guide/practices/page-sizes)

采用 Material 3 页面/面板/开关/选择控件，保持石墨色系；触点至少 48dp，字体响应系统缩放，危险动作有文字说明。320dp 窄屏、横屏、分屏、字体放大、TalkBack、硬件键盘和深浅色均纳入验收。状态栏/导航栏/IME insets 不得重复扣除或遮挡操作区。[触点与语义](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)、[窗口 Insets](https://developer.android.com/develop/ui/compose/system/insets-ui)

### 9.2 A1 主机与配置首片（2026-10-29）

- 新增 `:domain` / `:data`，原生主机首页从真实私有 `home/.ssh/config` 派生；搜索名称/地址、添加与稀疏编辑、SSH 配置文本编辑、设置/关于导航及未保存返回确认已接入。没有生产假主机；终端连接入口暂显示功能尚未接入，不伪造会话。
- 配置/用户名/端口求值均经 Core；JNI 只传 UTF-8 bytes，不输出裸指针。绑定当前 9 项，62 项登记待办。普通主机排除通配/否定规则，缺省远端用户名保留空，不使用 Android UID 名称。
- 首片对未改字段不写回；保存前校验非目标行保持原文。当时 Core 非连续重复指令可能破坏中间行，因此拒绝该类表单写回；后续共享修复与设备回归见 §9.4，这条拒绝不再是当前能力限制。
- 写盘采用进程锁 + 文件锁、文件身份与 SHA256 复核、强制独占备份/同步、同目录独占暂存/同步、提交前再次检查与 `ATOMIC_MOVE` 替换。备份或替换失败保留原文件；替换后目录同步失败明确报告“已替换但同步失败”，不谎称原文未改。
- `HOME` 仅在 Android 应用进程内设置为私有 home；相对 Include 和 `~/.ssh` 仍走 Core 原有语义。配置缺失显示空态，目录/读取/无效 UTF-8/不可访问 Include 显示错误。

### 9.17 按键重复、释放与焦点归属（2026-10-30）

本片延续 `a811aaf` 的布局字符接缝，补齐 `KeyAction.PRESS/REPEAT/RELEASE` 经 TerminalSurface → 私有 JNI 命令 → native owner → VT 的链路；不修改共享 Core ABI，不在 Kotlin 拼协议字节。VT 每次按当前模式编码；传统模式的释放不产生输入，Kitty 开启事件报告时才按模式发出释放/重复序列。释放不将滚动视口拉回底部。

`TerminalView` 按设备 ID 与 keycode 保存已发送的按下状态。只有本 View 接收过按下，后续长按才是 REPEAT；没有匹配按下的 key-up 不补造事件。单次软 Ctrl 在首次按下后从 UI 释放，但在同一次物理按键的重复/松开期间保持修饰，下一键不继承。复制/粘贴快捷键、选区操作及组合输入消费掉的按下不会单独生成释放。

View 失焦、窗口失焦、卸载，以及切换 surface **之前**，向原 owner 发送已按住键的释放并清除集合。迟到 key-up 不进入新会话，也不重复释放。辅助键和 IME 的按键式操作是一次完整点击，产生 PRESS/RELEASE；整段文本提交保持原有键入语义。单独修饰键、死键组合、数字键盘和真实外接键盘矩阵仍须继续实现/验证；不能把本片当作全部键盘能力完成。

### 9.18 修饰键、数字键盘与组合音符（2026-10-30）

本片基于 `237ea83`，已完成当前模拟器档位的切片验收；失败与恢复过程保留如下。左右 Shift/Ctrl/Alt/Meta、Caps Lock/Num Lock/Scroll Lock、数字键盘数字/运算符/Enter，以及 Print Screen/Pause 已有 native 映射；JNI 接受 VT 定义的十位修饰状态（含 Caps/Num Lock 与左右侧位），范围外仍拒绝。单独按修饰键或锁定键不消耗软 Ctrl 的单次状态，下一次字符按下才消耗；释放/重复仍沿 §9.17 的归属规则。映射存在不等于每个键都已单独验收，Print Screen/Pause、全部运算符和其他物理布局仍需补证据。

### 9.22 A3 共享主机信任前置（2026-10-30）

实现提交 `f5aaf18` 修复共享 C known_hosts 标记误信任，并同步 macOS 消费者；**没有新增 Android SSH JNI、连接页面或 Keystore 接线**。A3 仅完成这一共享前置，A2 的真机/release/长负载与完整键盘矩阵仍独立待办。

`gt__kh_visit` 将 marker 传给匹配器，`kh_check` 扫描完整文件，不因先遇到普通匹配就返回。匹配主机及密钥的 `@revoked` 优先拒绝；其他主机/密钥的撤销不影响当前普通信任。主机列表支持 `*` / `?` 和否定项；文件打开（ENOENT 除外）、读取及关闭失败不再降为未知。同步握手返回明确错误，公开异步状态新增 `GT_SSH_AUTH_HOST_REVOKED`；原枚举值和 73 个导出符号不变，Swift 增加 `.revoked` 及拒绝提示。

### 9.23 主机信任保存失败阻断（2026-10-30）

### 9.24 共享连接配置准入与两端接线（2026-10-30）

本片补齐“配置能够解析，但连接执行忽略它”的阻断入口。新增 `gt_config_check_connection`，两端复制同一 C 结果，显示指令名称、文件/行号与包含来源。检查只读取解析树，不改原文、不执行条件命令、不解析 DNS；从索引 0 枚举，`GT_ERR_UNSUPPORTED` 表示一项问题，`GT_OK` 表示结束并清零输出。字符串借用至配置编辑/释放；Swift/JNI 必须及时复制。参数非法返回 `GT_ERR_INVALID_ARG`，两端超过 255 项问题明确报错，不截断后继续连接。公共符号增至 **74**，Apple **72 引用 / 2 登记未用**，JNI **20 引用 / 54 待办**；NAPI 尚未实现。

本次定义的是当前普通连接的显式配置准入范围；通过检查不表示 Android 已有 SSH，也不表示凭据可用或远端能力存在。只检查用户显式指令，不把求值器内置默认集当成执行承诺。指令名和值中的枚举不区分大小写，数值仍按下表精确检查。

| 显式指令 | 当前允许的值 |
|---|---|
| `HostName`、`User`、`IdentityFile` | 单个非空参数，不能包含 `%` 或 `${` 展开；仍不承诺完整路径/身份语义验证 |
| `Port` | 单个十进制数，1–65535；非法值保留在编辑器并阻断连接，不因 Swift UInt16 转换崩溃 |
| `ProxyJump` | `none`；实际跳板链未实现 |
| `ServerAliveInterval` | 字面值 `0`；非零保活未接线 |
| `AddressFamily`、`StrictHostKeyChecking` | 分别只允许 `any`、`ask` |
| `ForwardAgent`、`ForwardX11`、`Compression`、`AddKeysToAgent`、`CanonicalizeHostname`、`CheckHostIP`、`HashKnownHosts`、`GSSAPIAuthentication`、`HostbasedAuthentication`、`PermitLocalCommand` | 只允许 `no` |
| 其他指令 | 有效已知选项、适用的未知指令均报不支持；包括转发、命令、算法和环境控制等 |

检查复用 Host 通配/否定规则，排除其他主机；已知标量和 first-list 只检查首个生效指令，累积列表逐项保留来源。Include 展开后沿用原文件/行号，未知行仍原样保存。任意 `Match` 都保守拒绝，包括可能位于前一个不匹配 Host 之后的条件；不运行 `Match exec`。这一档位参考 [OpenSSH 配置语义](https://man.openbsd.org/ssh_config.5)，但没有实现全部条件、展开或跨选项优先关系。例如 `ProxyCommand none` 仍按未知指令拒绝，不能据此宣称完整 OpenSSH 兼容；`IdentityFile none`、特殊用户路径等完整身份语义仍需后续处理。

macOS 在 `HostListModel` 从同一配置生成解析字段与问题快照，`SSHConnectionTarget`/`RemoteTarget` 保存快照；普通 SSH、独立/内嵌 SFTP 和远端 tmux 均带入共享 `SSHAuthenticationFlow`。流程在启动解析器之前报告不支持，不弹主机信任或凭据框。嵌入文件面板和 tmux 创建的会话继续保留原请求的问题快照，编辑配置只影响下一次从配置创建的请求。显式传入地址的内部调用仍可不附配置问题；不能将其误称为对任意字符串配置的自动校验。

Android 主机按钮经 `HostsViewModel → ConfigRepository → ConfigBridge → C` 在 IO dispatcher 检查当前快照；有问题时显示来源并保留配置编辑入口。没有问题时仍显示“SSH 连接正在接入，当前版本可管理主机与 SSH 配置”，没有创建连接或显示假成功。真正的 DNS/SSH owner、认证状态页面、取消和 Keystore 仍属 A3 待办。

### 9.25 Android SSH 认证与远端终端后端（2026-10-30）

新增 `RemoteSession`、`ResolvedSSHConnection`、`SSHAuthState` 与 `ssh_session.c`。本片把公开异步认证接入真实 Android native owner，并在认证后打开远端 PTY/shell，复用已有 VT、输入/resize、快照与关闭链。主机首页仍只做配置检查并提示 SSH 正在接入；没有将未完成的认证、身份页面提前开放。DNS、配置目标生成到连接的产品接线、Keystore、远端会话列表及 Activity 生命周期仍待后续 A3。

`ResolvedSSHConnection` 接收原始主机身份、用户、端口、绝对 known_hosts 路径、已解析二进制地址及 DNS 后剩余认证预算。地址数组立即复制；网络地址不替换主机验证身份。产品 DNS 尚未实现，测试使用 adb reverse 的显式环回地址，不记为 DNS 验收。新的 API 仍只经聚合头消费 C；公共符号 **74** 不变，JNI 现 **32 引用 / 42 登记待办**，Apple 仍 **72/2**。

线程与资源契约：

- `session_jni.c` 的同一个 native owner 完成认证、SSH shell、Transport 读写和 VT feed；`TerminalView`/surface 不区分本地与 SSH，原始输出不进 Kotlin 或 UI。
- `gt_ssh_authenticator_*` 的 step、info、decide、supply、take/close 均在 owner 串行执行。JNI 只复制低频状态与排入一次响应；未知主机停在确认状态，发现服务器方法后才请求凭据。
- 快照保留 phase、错误码、host 状态、deadline、方法表、算法和 SHA256 指纹。未知、变化、撤销与不支持不折叠；保存信任失败保留 IO/UNKNOWN 原因，停止且不索取凭据。
- 每次提示有递增请求号；已提交/非等待状态返回请求号 0。响应同时检查 native 会话代次、Kotlin 快照归属、请求号、阶段和方法表。失败重试产生新号；旧请求和其他会话的请求明确拒绝。
- 密码/已解锁 PEM 只以可清理 ByteArray 传入，成功、非法输入或过期请求均擦除调用方缓冲；JNI 拷贝在 owner 消费/失败/取消后擦除。NUL 拒绝按原始长度擦除，不能漏掉 NUL 后的内容。状态和错误不包含凭据内容；没有增加明文私钥存储。该入口不等于 Keystore 容器、导入/解锁页面已完成。
- 关闭立即撤销句柄并设置取消位，UI 不 join；等待信任或凭据时仍推进总 deadline。owner 完成后释放认证/SSH/VT；正常 EOF 关闭 Transport 和专属 SSH，保留 VT 供浏览。共享 SSH backend 当前无法确认 exit-status 是否到达，远端退出码保留未知，不能因命令是 `exit 7` 就填 7 或 0。

**仍需收口的取消边界**：普通 `gt_transport_open_ssh_shell` 使用共享的 5 秒通道预算，没有取消回调；本片只在进入前与返回后检查取消。UI 关闭不阻塞，但不能把认证等待阶段的快速释放证据扩大为通道请求中的同等取消时限。下一片须结合产品总 deadline/取消补齐该段，而不是伪称全部连接阶段均已验证。成功密码认证、加密密钥/口令检测、IPv6、网络切换/断流、真实 DNS 与远端终端像素尚无本片证据。

性能证据至少记录设备/API/ABI、持续输出吞吐、帧耗时、峰值内存、空闲后台 CPU、输入到回显延迟与取消耗时。先测 A2 基线再锁门限；不能用模拟器或静态截图冒充真机流畅度。真正的 UI 测试要驱动按钮、手势与系统 IME，数据模型测试不能代替触控命中与像素检查。
