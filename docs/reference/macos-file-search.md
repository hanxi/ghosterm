# macOS 文件搜索

搜索统一经过 FileBackend，普通本地与远端面板使用相同名称匹配：不含通配符时忽略大小写包含，含 `*`/`?` 时匹配整个名称，方括号为字面量。远端 find 仅输出 NUL 分隔的路径，再由同一匹配器过滤；不再让远端 locale 或 find 的额外 glob 语法改变含义。命令目录单引号转义，先 realpath，返回路径严格 UTF-8 且必须位于该根下。

搜索范围默认最多 64 层并在页面说明，根自身不作为命中；可调用更浅的范围。超过 5,000 个结果、100,000 个扫描项、8 MiB 结果名称/路径元数据，或远端 16 MiB 输出/单路径 64 KiB 上限，显示未完成并保留已收到的条目，不显示正常完成。远端读取另有 60 秒预算；这不是进程 RSS 限额。累积结果按路径 UTF-8 字节去重，进度首次命中/每百项发布不可变快照，避免逐条入 UI 队列。文件列表的其它 String 选择/树键仍待统一字节身份。

只有打开 exec 明确返回 `GT_ERR_UNSUPPORTED` 才进入 SFTP walk；网络、认证、读取或命令执行失败不回退。stderr 非空、非零或未知退出状态、缺失 NUL 尾帧、无效/越界路径及条目 lstat 失败都属于搜索未完成。现有明确退出状态接口直接消费，不把未知当零。保留部分结果、扫描量与错误；重试使用原查询/深度重新扫描，旧结果清空，不继承错误。

取消令牌实际传入远端读取循环与 walk，每个扫描项（包括未命中）都会检查；无输出 read 使用 100 ms 片段，超时仍检查取消/总预算。本地 visitor 也协作停止；尚未开始的旧搜索跳过路径查询。取消或启动新搜索后，旧进度/成功/错误均不能重新发布；目录切换尚未结束时启动的旧目录搜索，也在新目录提交时取消；面板释放也取消令牌。exec 读取无论结果均关闭通道。

取消界面立即返回，但旧 Core 的 exec 打开/同步关闭、SFTP 单次枚举/元数据读取和本地文件系统调用尚无贯通的可取消 deadline，因此不宣称所有网络阶段有界释放。文件后端仍使用同步串行 owner 接口；传输与预览迁移另行验收。服务器没有 find 或不支持选项时显式失败，不偷偷换一种执行策略。

本地 list 不再跳过 lstat 失败项；walk 对根类型、逐项元数据与枚举错误明确抛错，不缓存为空。用枚举器原生层级判断深度，到范围边界不再进入子目录；符号链接不递归。权限修改的扫描/链接错误与目录传输结果仍是独立待办。
