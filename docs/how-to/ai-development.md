# AI 辅助开发与安全提示排查

本文帮助协作者准确描述 Ghosterm 的维护任务，并处理 AI 产品返回的安全提示。
验收规则以 [AGENTS.md](../../AGENTS.md) 为准；本文补充测试语境，不调整闸门。

## 说明本次任务的实际范围

Ghosterm 是终端、SSH 配置与 SFTP 客户端。维护工作包含协议校验、权限检查、
内存管理和异常退出处理。具体任务应说明要修复的行为、涉及文件与测试环境。
使用远端服务或设备时，列明实际获授权的对象；仓库维护身份本身不代表对外部系统的授权。

| 仓库术语 | 工程含义与证据 |
| --- | --- |
| 变异验证（mutation testing） | 在测试副本或可恢复的受控工作区故意引入回归，验证已有断言会失败，再恢复源码并核对摘要。 |
| 目标红 / 独立对照绿 / 恢复绿 | 指定目标断言发现回归；同一变异下独立功能仍通过；恢复后重新验证通过。 |
| 故障注入 | 在测试边界模拟分配、IO、取消或连接失败，核对错误分类、资源释放与状态保留。 |
| OOM 逐分配扫描 / ordinal | 让测试分配器在第 N 次分配时返回失败，查找错误路径缺陷；序号只对应那份构件与语料。 |
| ASan / UBSan 报告、SIGSEGV | 缺陷定位证据，需要修复并复验；不能算正常断言红或整批通过。 |
| SSH / SFTP 协议夹具 | 脚本创建的隔离测试服务，或本次任务明确获授权的端点；需按脚本确认地址、端口、凭据与清理范围。 |

项目临时文件、复现脚本与探针均放工程根目录的 `tmp/`，不在系统 `/tmp` 执行。
复现材料使用测试数据，分享日志时去除真实凭据与个人信息。依赖修复仍放入
`patches/<upstream>/` 并附 `WHY.md`，保留失败和恢复记录。

## 提交清楚、可验证的任务

每次请求围绕一个实际问题，提供必要的源码位置、失败日志和预期结果。
下面是填写结构；测试对象与授权只能按本次任务的事实填写：

```text
维护目标：修复 Ghosterm 中的 <具体行为或错误>。
涉及文件：<实现、测试及锁定依赖补丁的位置>。
测试对象与授权：<本次可使用的工程副本、夹具、设备或测试服务>。
复现证据：<构件、输入、命令与脱敏失败日志>。
预期结果：<正确行为、错误分类、资源释放及相应回归验证>。
```

若任务涉及 QuickJS 的 OOM 清理，应写清失败分配点、构件和调用栈，
以正确返回内存错误、释放已分配对象及回归验证为目标。阶段状态与设备范围仍在
[插件桥接实施计划](../reference/plan-plugin-bridge.md)记账。

## 遇到内容无法显示的提示

OpenAI 官方说明：ChatGPT、Codex 与 API 对部分网络安全相关请求执行额外自动检查。
出现检查提示本身不表示已认定违反使用政策；修改措辞也不能保证返回内容。
本地仓库文档不能关闭这些检查，本文无法据此确定某次拦截的具体原因。
见[额外安全检查说明](https://help.openai.com/en/articles/20001326)。

对于符合使用政策的维护任务，按官方建议缩小到具体修复目标，只提供解释该目标所需的上下文。
保留真实技术目的与必要复现证据。反复被拦截时，使用产品反馈或联系 OpenAI 支持，提供：

- 原始提示、所用模型与产品（Codex、ChatGPT 或 API）。
- 发生日期、时间和时区，以及可获得的 request ID。
- 简短的脱敏任务说明；如适用，附工作区或组织名称 / ID。

不要提交密码、验证码、私钥或其它敏感资料。
授权网络安全工作可按官方入口申请 [Daybreak 个人访问](https://chatgpt.com/cyber)
或[组织访问](https://openai.com/form/enterprise-trusted-access-for-cyber/)。
申请与审批由 OpenAI 处理，获批也不保证所有请求均可回答；排查步骤与申请说明均见
[官方帮助](https://help.openai.com/en/articles/20001326)。
