# 在真实手机上验收 Android 客户端

本页用于补齐[实现计划 §10.1](../reference/android-implementation.md#101-当前完成审计与剩余验收2026-11-03)的手机证据。模拟器结果、构建成功和用户的一句“正常”分别保留各自范围；某项没有条件测试时填“未测”。安装来源与当前固定签名 release 见 [Android 出包说明](android-release.md)。

## 记录设备与版本

在系统设置记录手机型号、Android 版本、使用的输入法及版本。打开 Ghosterm 的“设置 → 关于 Ghosterm”，记录源码提交和构建状态；滚动 dev 链接会更新，验收应绑定这次实际安装版本。覆盖安装后先核对原主机、身份、文件及历史仍可访问，再开始新测试。

## 验证 SSH 和主机身份

1. 使用自己的测试主机，通过域名连接，核对服务器公开主机指纹后完成认证。
2. 若使用导入身份，在认证弹窗选择密钥并保留默认勾选“记住此密钥”，完成一次成功连接。当前版本的发行记录见实现计划末尾；旧 `0c30b17` 仍需在“编辑主机 → SSH 身份”关联并保存。记住操作不改 SSH 配置，仍可在主机编辑中显式关联。
3. 关闭刚才的连接，再创建两次新连接，其中一次在结束并重新打开应用后进行。已记住或关联的无口令身份应自动尝试；带口令的身份仍需解锁。分别记录“要求选身份”和“要求输入解锁口令”，两者不是同一操作。
4. 从已连接终端点“文件”，应列出该会话实际主机的文件；打开一个已知文本文件，再返回终端，应仍能输入和收到输出。

对同一台服务器分别记录域名与 IP 的结果，不用另一台服务器的成功代替失败场景：

| 手机网络状态 | 域名解析/到达指纹 | 认证与终端 | 远端文件列表/文本预览 |
|---|---|---|---|
| Wi-Fi |  |  |  |
| 移动网络 |  |  |  |
| 实际使用的 VPN |  |  |  |
| 实际使用的私人 DNS |  |  |  |
| 已连接时切换网络 |  |  |  |

切网后记录实际断开/错误及重新连接结果；不要将旧画面仍可见记成连接正常。配置文本测试可在编辑页输入域名、两空格缩进及换行，核对候选文字后取消；无需修改真实主机配置来测试输入法。

## 验证文件复制

只使用自己创建的独立测试目录和非敏感文本。准备包含中文、换行和唯一测试标记的小文件，另准备空目录与同名但内容不同的目标文件。源与目标的实际内容分别核对；能用桌面或服务器工具时额外记录 SHA256。

每次从文件浏览开始：点按文件应打开预览，返回后长按才进入选择；点“复制”，核对待粘贴卡片的条目和来源；切换到目标位置，点“粘贴到当前目录”，核对来源/目标和冲突选择，再明确确认。完成后读取目标内容，并确认原来源和已有目标仍符合所选决策。

| 方向或边界 | 来源/目标的可区分名称 | 实际结果与内容核对 |
|---|---|---|
| 应用文件 → 应用文件 |  |  |
| 远端 → 应用文件 |  |  |
| 应用文件 → 远端 |  |  |
| 远端 → 另一远端 |  |  |
| 系统或第三方提供方 ↔ 应用文件 | 提供方名称/版本 |  |
| 空目录、同名“保留两者”、跳过 |  |  |
| 取消、断线、授权失效 |  |  |

只读服务只能作为读取来源。失败和取消要记录界面状态、已知目标是否改变；无法核对时填“无法确认”，不写“没有副作用”。重启应用后检查测试历史仍能打开；它是上次观察记录，不代表应用已经重新核验目标。清理时只处理自己的测试文件，删除历史与删除文件分别操作。


反馈不需要私钥、口令或完整 SSH 配置。主机名、路径和用户名可替换为固定代号，保留不同位置的对应关系。
