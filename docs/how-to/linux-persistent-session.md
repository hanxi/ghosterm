# 从 macOS 使用 Linux 持久会话

应用包需包含匹配的 macOS helper 与 Linux aarch64/x86_64 预编译环境。
当前随包 Linux 环境要求 glibc ≥ 2.34；未提供 musl 包，探测不符会明确失败。
在 `~/.ssh/config` 配置 Linux 主机，侧栏点主机连接。首次连接确认主机指纹并按
服务器支持的方式认证；应用探测架构与依赖，随后经同一 SSH 端口上传并校验 Linux
环境包，随后启动 SSH 环境中的用户登录 shell。远端不编译、不执行 apt/yum、不需要 sudo，也不开放额外公网端口。

远端默认安装目录为 `$HOME/.ghosterm/sessiond`，运行目录为
`$HOME/.ghosterm/runtime/<contract-prefix>`。缺失的目录按 0700 创建；若家目录或已有的
`.ghosterm` 目录由他人拥有、允许组/其他用户写入，安全校验仍会拒绝，应用不会自动改权限。
本机会话使用同一套 C 宿主与恢复逻辑，但本机运行目录不随此变更迁移。
旧的远端会话仍指向记录中的原运行目录（包括旧版的 `.local/state/ghosterm`），
更改默认路径不会迁移或终止后台会话；旧目录权限不安全时，旧会话仍无法恢复。

- 网络中断后，保留窗格等待重连；连接恢复后接回原 shell，而不是重新执行命令。
- 暂时离开时，在标签右键菜单选择“断开并保留会话”，或直接退出应用。重新启动
  应用时自动恢复已确认的会话，也可以从侧栏“保留的会话”选择恢复。
- 要结束后台程序，关闭标签页/窗格，或在保留会话上选择“终止会话”。终止结果
  未知时先用“检查状态”确认；应用不会自动重发未知停止或未知输入。
- “遗忘记录（保留后台会话）”只删除本机恢复记录，后台进程仍可能运行。
- 反过来不成立：会话一旦**结束**（daemon 在最后一个客户端脱离时已回收它），
  恢复只会得到“找不到”，所以这条记录不再列进侧栏，也会在下次读取时被清掉。
  已结束**窗格**不受影响——它还留着最终画面与已知/未知退出状态，可以显式关闭。

退出会中断文件传输和正在建立的连接；已经建立的终端会话继续由 daemon 持有。
已结束的终端保留最终画面与已知/未知退出状态，可以显式关闭。当前启动恢复逐个
打开会话；没有承诺恢复原窗口分组、分屏布局或标签排序。

首版协议与快照使用严格匹配的版本契约。契约不符会明确拒绝，不把旧后台会话
当成新会话，也不自动迁移。升级前应先处理旧会话；后续兼容策略另行设计，见
[远端会话架构](../architecture/remote-session.md)。

当前证据为 macOS arm64 客户端→Linux aarch64 原生环境，以及 Linux x86_64
的 QEMU 用户态环境。SSH 到 macOS/Windows 延后；完整 P0 资源预算仍未完成。
